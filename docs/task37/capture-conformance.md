# Capture conformance inventory

Capture is optional synchronous observation, not a recorder backend or attempt coordinator. Core owns requirements/session/report and injected sink/projector ports; the generic adapter executor owns checked sync/buffered binding. The first actual raw native SDK hook is OpenAI Chat Completions. SDK JSON is semantic capture, not original HTTP/SSE bytes. No current adapter promises transport byte capture or physical attempt identity; requests requiring that coverage fail before dispatch.

OpenAI SDK retries are disabled per sync/native call (`WithMaxRetries(0)`), even when its injected client is configured differently. The logical invocation ID is never copied into PhysicalAttemptID. The HTTP 503 fixture proves one request for each mode; required physical attempt coverage remains unsupported. Applications own retry/reconciliation policy and must not replay partial output or assume a capture error means no execution occurred.

Backpressure is synchronous: no queue, producer goroutine, storage/blob or retention service is added. Emit serializes delivery per session and permits Report reads from callbacks; re-entering Emit from a callback is prohibited. Delivered payload is bounded by MaxBytes (default 64 KiB); this is not a bound on SDK response allocation. Sink/projector must honor cancellation. Callback failure and early consumer stop retain readable status and release the source according to the stream contract.

These fixtures establish actual adapter/port behavior on their declared local bindings, not live-provider/account support or all model features. Broader profile-specific conformance remains separately tracked; final independent audits have not been replaced by this inventory.
