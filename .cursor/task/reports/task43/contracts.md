# Task43 — provider capability contracts

Статус: design/implementation in progress; это не отчёт приёмки. Все направления task43 остаются обязательными. Проверена база `132afc2` и установленные SDK: OpenAI v3.24.0, Anthropic v1.26.0, Gemini v1.48.0, Ollama v0.17.4.

## Общие инварианты

Поддержка задаётся caller-owned profile для точного provider/endpoint/model. Поля SDK доказывают только наличие mapping. Неизвестные capabilities, settings и запрещённые profile combinations отвергаются до IO. Нет автоматического discovery, download/upload, resume, retries или agent loop. Original-schema validation, state scopes, capture redaction и usage presence сохраняются. Локальные HTTP/SSE fixtures не доказывают live model conformance.

## Матрица проектируемых портов

| Endpoint / operation | Feature / inputs | Profile gate | Port / результат |
| --- | --- | --- | --- |
| OpenAI Responses / foreground create | reasoning effort и summary; native strict local tools | собственная ModelOptionsSchema Responses; явная strict capability; совместимая исходная schema | Responses Create; summary отдельно от encrypted state; original args validation |
| OpenAI Responses / foreground create stream | mixed output, functions, hosted search, reasoning, usage | response_create + native_stream и capabilities фактического запроса | отдельный native create stream; общий single-use/Close lifecycle; observed handle и partial response |
| OpenAI Responses / get, cancel, background | существующие explicit operations | operation-only gates; background отдельно | существующие порты; без SSE polling и reconnect |
| Ollama / chat sync и native stream | ResponseFormat → native Format | structured_output; оригинальная schema без lowering | существующий checked client; validation только завершённого output |
| Ollama / chat sync и native stream | ProviderSettings.think → верхнеуровневый Think | reasoning + эффективная ModelOptionsSchema; forbidden combinations | существующие ChatRequest/stream; thinking не включается в JSON output |
| Gemini GenerateContent / sync, stream, batch | text/image FunctionResponse с ID | отдельная media-result capability + InputMIME + backend/forms | существующие SDK FunctionResponse.Parts; bytes/URI caller-owned; порядок и scope без потерь |
| Anthropic Messages / sync, stream, batch | явно объявленные hosted search/fetch; server blocks, citations, pause | отдельные hosted capabilities; versioned adapter declarations | provider-scoped ordered history; hosted не становится ToolCallPart; caller отдельно продолжает pause |

Сигнатуры Responses native port и versioned Anthropic declarations закреплены в реализации и SDK fixtures; независимая приёмка ещё не выполнена.

## Responses: controls и strict tools

ProviderSettings разрешает только `reasoning_effort` (none/minimal/low/medium/high/xhigh) и `reasoning_summary` (auto/concise/detailed). Это отдельный Responses whitelist. Любой из ключей требует reasoning capability и эффективной ModelOptionsSchema; та задаёт фактические значения и combinations модели. Summary не включает encrypted state автоматически: encrypted include по-прежнему определяется отдельным provider-state requirement. Deprecated generate_summary не поддерживается.

RemoteResponseRequest.StrictTools — явный opt-in для всех local tools данного Create; требует хотя бы одного local tool и capability `strict_tools`. Обычные tools отправляются с explicit strict:false. При strict:true исходная schema должна быть совместима с ограниченным adapter strict subset: object root, закрытые objects, все properties required, поддержанные schema keywords/children. Никаких преобразований, даже при разрешённой SchemaLowering policy. Проверяется оригинал, а не изменённая schema; аргументы после ответа проходят существующую original validation. Hosted tools не получают local strict flag. Get/Cancel проверяют сохранённую original schema binding без повторного требования capability strict_tools.

Источники: [reasoning](https://developers.openai.com/api/docs/guides/reasoning), [function calling](https://developers.openai.com/api/docs/guides/function-calling). Запрошенный summary — видимый summary, не raw reasoning. Native strict требует закрытых объектов и обязательных properties; caller решает nullable semantics в исходной schema. SDK-поля не доказывают модельную поддержку.

## Ollama: исполняемый контракт перед реализацией

- Новый allowlisted ключ `think` в ProviderSettings передаётся в верхнеуровневый `api.ChatRequest.Think`, а не в `Options`. Типы: bool, null, string `low`/`medium`/`high`. Это граница установленного SDK v0.17.4 (`ThinkValue.IsValid`/`UnmarshalJSON`); прочие именованные уровни не объявляются реализованными.
- Даже `think:false` и `think:null` требуют reasoning capability и эффективной ModelOptionsSchema: они выражают model-specific control. Profile schema ограничивает конкретные допустимые значения и сочетания. Не выводить поддержку из имени модели, не вызывать `/api/show`.
- ResponseFormat требует structured_output и передаёт исходный JSON Schema object в `Format` без добавления его в prompt. Mapper возвращает точную копию документа; неподдержанная форма schema — явная ошибка fidelity. Original schema компилируется существующим schema engine и используется для проверки конечного ответа.
- Nonterminal native JSON chunks provisional. Refusal/incomplete не превращаются в schema success. ReasoningPart относится к отдельному каналу reasoning и не входит в JSON output; иные non-text output parts остаются ошибкой.
- Translate с этими новыми features также требует profile, включая direct/raw translation; для checked sync/native сохраняются существующие preflight и original-validation paths. Ошибки capabilities/options/schema не вызывают Chat.

Документация сверена 7 октября 2026: [structured outputs](https://docs.ollama.com/capabilities/structured-outputs) описывает schema в Format и не заявляет поддержку cloud; [thinking](https://docs.ollama.com/capabilities/thinking) описывает model-specific controls и server fallback для неизвестных уровней. Библиотека вместо такого fallback отвергает неподтверждённый control.

## Gemini: multimodal function results

Capability `gemini.function_result_media` (adapter-owned extension) подтверждает endpoint/model для text/image results. InputMIME дополнительно проверяет каждый nested image. Поддержанный image subset: image/png, image/jpeg, image/webp. Inline bytes доступны обоим GenerateContent backends; URI — только Vertex GCS `gs://bucket/object` без query/fragment/userinfo. Gemini API FunctionResponse документация разрешает только inlineData, поэтому URL там отвергается, несмотря на наличие FileData в общем SDK. Иные MIME/media types и одновременно bytes+URI отвергаются до IO. Не выполнять download/upload.

У результата с media `response.output` (или `response.error`) — ordered array: text остаётся string, image заменяется единственной ссылкой `{"$ref":"prompty_part_N"}`; `parts` содержит изображения в исходном порядке с соответствующим уникальным displayName. N — индекс в исходном Content, не ToolCallID. Это provider-native структурированный JSON, сохраняющий смешанный порядок; ID и name FunctionResponse остаются исходными. Text-only results сохраняют прежний native output/error string. Canonical execution/wire остаётся ToolResultPart с исходным Content и не получает vendor DTO.

Источники: [Gemini GenerateContent function calling](https://ai.google.dev/gemini-api/docs/generate-content/function-calling?hl=en) и [Vertex function calling](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/multimodal/function-calling). Они описывают nested FunctionResponse parts и одноразовые displayName references. Наличие функции у конкретной модели устанавливает host profile, а не имя модели.

## Native stream: универсальная финализация логического part

Текущий Stream сохраняет text/reasoning fragments отдельно. Для финального native source-bound reasoning нужен explicit `StreamPartFinalization`: PartID, полный Content, optional ProviderState envelope, annotations с локальным PartIndex=0. Это не дополнительный delta: он сворачивает уже опубликованные fragments этого ID в первый исходный индекс и пересчитывает associations остальных частей. Соответствие text/reasoning — точная конкатенация; tools — существующая assembly ArgsChunk/Args. Изменять смысл, тип, cache metadata или ранее state-bound content запрещено. Unknown ID, duplicate finalization, state binding conflict и deltas после finalization — protocol/state errors. Операция атомарна: invalid finalization не меняет retained prefix. Она применяется при приёме кадра, до EOF, поэтому поздняя ошибка сохраняет финализированную часть/state, но отзывает continuation всего failed exchange. Producer обязан создавать opaque source-order manifests только после стабилизации индексов; core не декодирует vendor payload.

Responses CreateStream использует общий Stream lifecycle плюс отдельную operation-local metadata обёртку для cloned remote handle/result. SDK NewStreaming вызывается только в lazy source, retries=0, context cancellation + Close закрывают тело. Whole-JSON responseSource.observe не применим к SSE: он полностью читает тело. Stream capture отражает прочитанные semantic events и отдельный end record с observed event count/completeness, не original HTTP coverage. Background/поллинг/Get/reconnect в native create не допускаются.

Порт закреплён в core: RemoteResponseStreamer.CreateStream(ctx, RemoteResponseRequest) RemoteResponseStream. Возвращаемый интерфейс делегирует Events/Close/Status общему Stream и добавляет RemoteResult() с owned snapshot remote handle + canonical observed response/diagnostics. Это отдельный optional port, а не обязательный метод каждого Invoker/RemoteResponseManager. Profile/schema preparation и owned request snapshot создаются без IO при создании handle; dispatch и повторная проверка истечения continuation выполняются в lazy consumption. Portable remote handle и response wire сохраняются отдельно. SDK DTO и event machine остаются в адаптере.

Финализация reasoning прикрепляет полный native item с encrypted_content, а не state пустого delta. Если item.done ещё не содержит encrypted state, producer проверяет summary, но ждёт terminal source для finalization; отсутствие state окончательно объявляется только после известного terminal. Если state уже доступно на item.done, оно должно сохраняться при последующей ошибке. Повторные final source items обязаны согласовываться с наблюдённым содержимым/state; несовпадение не исправляется переписыванием prefix. Text citations относятся к полному text part. Hosted source-order manifest создаётся после стабилизации всех logical part indices. SDK union не имеет события response.usage: usage читается только из реально присутствующего Response.Usage recognized events.

## Anthropic: выбранный контракт для следующего этапа

Pinned kinds: `anthropic.web_search_20250305`, `anthropic.web_fetch_20250910`. SDK v1.26.0 представляет обе в обычном Messages API; варианты 20260209 с dynamic filtering/code execution не входят в mapping.

Объявления доступны как generic HostedToolRequest в canonical PromptExecution с deep clone, execution wire и batch digest. RemoteResponseRequest.HostedTools удалён; aliases/merge policy нет. Execution-wire остаётся v2: необязательный hosted_tools имеет closed declaration shape; settings — object, concrete meaning интерпретирует адаптер. Конкретные kind/settings/SDK DTO остаются в адаптере. RuntimeDescriptor.HostedToolCapabilities связывает реализованный adapter kind с profile guarantee; profile override не может создать отсутствующий mapping. Любой адаптер без такого mapping отвергает intent в checked preflight и direct Translate. Hosted declarations не входят в локальный ToolScope и не разрешают запуск handler.

Search whitelist: max_uses, allowed_domains, blocked_domains, user_location. Fetch whitelist: max_uses, allowed_domains, blocked_domains, max_content_tokens, citations.enabled. Limits — положительные целые; domain lists взаимоисключающие; user_location.type только approximate, остальные поля city/region/country/timezone. Unknown keys, caller/code-execution options и коллизии local names web_search/web_fetch отвергаются до IO.

Request mapping реализован через SDK OfWebSearchTool20250305/OfWebFetchTool20250910 без raw overrides; передаваемые settings клонируются и превращаются в owned typed values. Direct Translate отдельно проверяет требуемый profile, checked sync/native/batch preflight проверяет фактическую operation и combinations. Actual SDK request fixtures подтверждают fixed type/name, исходные settings, explicit citations.enabled:false и integer 9007199254740993. Zero-IO fixtures проверяют неизвестные kinds/profiles, запрещённые combinations, duplicate/nested duplicate fields, null/unknown/reserved settings и local-name collision. Это request mapping; hosted response/history/native conformance ещё не приняты.

Hosted server_tool_use/results/errors сохраняются через adapter-scoped MessageAnnotations и source-order manifest, никогда через ToolCallPart. Реализованы sync parse и hosted history replay: exact scope, ID/name/result linkage, duplicate IDs/results, типы blocks, текущие canonical text/citations/local/reasoning parts и целостность manifest. Source entries содержат проверенные raw text/local/hosted blocks; signed/redacted thinking представлены canonical part reference и SHA-256 digest приватного payload. Signature/data в публичный manifest не дублируются. Fetch result разбирается по RawJSON: SDK generic Content union предназначен для search и может потерять document.

Public HostedItems(response) возвращает owned records с BlockIndex/Type/ID/Name/ToolUseID/Input/Content/SourceJSON/Scope и сверяет каждый record со source. Search result сохраняет encrypted_content и optional page_age; fetch document сохраняет text/plain или base64 application/pdf без download/decode PDF. Missing document title и citation title/document_title:null не нормализуются. Known hosted errors, включая документированный fetch url_not_in_prior_context сверх SDK enum, остаются provider metadata, не transport/local-handler errors. Inputs server call — unique JSON objects; malformed model arguments не скрывают валидный invalid_tool_input hosted result. Pending calls разрешены только при pause_turn/tool_use/max_tokens; completed end_turn с pending call отвергается.

Generic RuntimeDescriptor.MessageAnnotationCapabilities связывает provider history annotation kinds с требуемыми profile guarantees. Они участвуют в той же actual-operation combination check, что новые declarations, включая native_stream; unsupported history feature отказывает даже без новых HostedTools.

Исправлена проверенная граница: hosted-only history без PartState ранее переносилась в OpenAI Chat с потерей metadata. Теперь foreign scope и отсутствующий required mapping отвергаются до IO. Закреплён общий контракт: MessageAnnotation.Scope — optional owned ProfileIdentity, Required — optional bool; Required:true требует валидный Scope. Core проверяет scope/shape, не разбирая Value или vendor kind. Scoped metadata, как part state, относится только к своему destination. Required kind дополнительно требует реальный mapping в RuntimeDescriptor.MessageAnnotationCapabilities, а capabilities/combination — знания профиля. ProviderStateAdapter должен валидировать required message metadata и при отсутствии PartState; dispatch snapshot включает такой metadata. Direct Translate также отвергает отсутствующий mapping. Unscoped optional metadata остаётся caller-owned.

Clone/wire/state policy: Scope и Value deep-owned; StatePreserve сохраняет markers; StateOmit удаляет scoped annotations и выставляет ContinuationUnavailable, если они Required. Optional unscoped annotations не удаляются. Conservative context reduction объединяет scoped-metadata-bearing messages так же, как part-state-bearing messages; Values не декодируются. Anthropic/OpenAI Responses producer помечает required hosted records/manifest, а decoder отвергает unmarked legacy hosted history. Synthetic output не заявляет hosted mapping, поскольку его отдельный parser этого не реализует. Поддержка нового marker в schemas остаётся расширением v2, без aliases или vendor DTO в core. Marker/gates/clone/wire/state-policy/context grouping реализованы и проверены targeted race + общими checks; task43 ещё не принята.

Incoming required metadata требует provider_state profile guarantee, но в Responses это не означает request нового encrypted reasoning output. Output guarantee определяется explicit CapabilityProviderState или прежним part-state intent; handle.ProviderStateRequired сохраняет эту output binding. Hosted-only history не добавляет reasoning.encrypted_content Include автоматически. Callback/dispatch snapshot включает scoped message metadata; ProviderStateAdapter применяется к Required annotations без PartState. Исправление cross-provider подтверждено тем же репро: foreign Translate accepted=false до IO.

Универсальный OutcomePaused отделяет завершение текущего HTTP request от completed model output; schema success для него не объявляется. Prepared adapter validation сохраняет валидную pause/state как control outcome, проверяя присутствующие local call arguments, но не валидируя output как completed JSON. Typed structured-output helper отвергает paused как non-completed output; one-shot typed-tool executor возвращает OutcomeError и не запускает handlers. Native Stream может завершить transport с OutcomePaused без отзыва валидного continuation. Caller продолжает отдельным запросом с неизменённой assistant message и явно выбранными hosted declarations. Ни resume loop, ни credentials/session service не создаются. Native stream накапливает server input_json_delta до stop, публикует только проверенные source-proven records; manifest порядок определяется native block indices. Batch использует тот же checked Translate/Parse и canonical binding либо отклоняет profile-forbidden combination до submit.

Источники: [Anthropic web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool). Эти settings и pause semantics требуют актуального endpoint/model profile; фиксированные SDK types не устанавливают live поддержку.


Hosted batch actual-SDK fixture сохраняет mixed success/error source и OutcomePaused, даёт unchanged assistant continuation через обычный Translate и отвергает изменённые hosted settings при result rebinding до download. Forbidden combination batch_submit+hosted_web_search проверена zero IO. ExampleHostedItems показывает response wire preserve, caller explicit resume и неизвестный hosted kind без нового SDK request. Targeted race: checks/hosted-batch-example-r1.log.


Native Anthropic использует общую StreamPartFinalization при закрытии text/local blocks: наблюдённые fragments сворачиваются без повторного content/annotations. Manifest canonical indices определяются native source order даже при interleaved close. Проверенный hosted prefix сохраняется при более поздней ошибке в том же flush; unfinished scoped metadata отзывает continuation через core lifecycle.
